# 功能自解释工程（2026-10-27）

目标：玲結美咲对**自己的每一个功能**都能讲清楚——能做什么、谁能用（额度）、参数怎么
填（给默认值）、走一遍实例、效果不对该动哪个旋钮；视觉类功能还能**现场生成演示图**
给用户看效果。覆盖范围不限于工作站：转换、图片、PDF、文本、二维码、音色复刻、
聊天语音气泡、Pixiv 生图都在内。

## 四件套

| 件 | 位置 | 作用 |
|---|---|---|
| 知识库 | `src/core/capabilities-kb.js` | 12 张教学卡：id/name/别名/summary/who（额度，暂定值已标注）/how 步骤/params（参数+默认值）/example（用户说 X→我做 Y→结果 Z）/tips（调参指南）/demo |
| 查询接口 | console `/api/help` + 工具 `qq_help` | 无 topic → 目录；有 topic（中文功能名/关键词，含别名模糊匹配）→ 整卡；查不到回建议清单 |
| 演示图 | `image-edit.js` 的 `demoWatermark`，走 `/api/image/edit` 的 `action=demo-watermark` | 程序化画样例背景（渐变+光斑，不碰用户素材）+ **同一条水印管线**渲染，返回 `applied`（实际生效参数）让模型照着讲。教学用途**不占媒体额度** |
| 教学规则 | preset `[TEACHING / SELF-EXPLANATION]` | 六条：先查卡再答/用样例教/默认配方先行/一屏讲完/诚实限额/新功能必须带卡 |

## 关键设计

1. **演示图和真实交付同一套实现**：demo 复用 `runPillowEdit` + `PILLOW_SCRIPT`，
   不存在"演示是一回事、实际做是另一回事"的漂移。
2. **三层理解机制**（对应"AI 听懂描述"）：
   - 代码层：`normalizeWatermarkColor` 颜色别名表，认不出的词报错指路；
   - 知识库层：每张卡的 params 给默认值、tips 给"动哪个旋钮会怎样"；
   - preset 层：口语翻译表（右下角→bottom-right、铺满→tile、红色→#FF0000）、
     反问协议（一次问齐、每个带建议默认值、用户可回"就这样"）。
3. **默认配方先行**：用户不会调参就给配方——角标（右下+白字+65%+4%）/
   全页防盗（平铺+-20°+密度5，图 0.4~0.6、PDF 0.12）；先演示、满意再动真图。
4. **参考图**：`node tools/make-watermark-demo.mjs` 生成 `assets/水印参数参考_20261027.png`
   （2×2 四宫格：默认角标 / 全页防盗默认 / 密度 5→12 / 金色+30°），可随时重新生成，
   也是水印管线最直观的目视回归。

## 卡片清单（12 张）

image-watermark（图片加水印）、image-edit（压缩/尺寸/裁剪/圆头）、image-gif（合成动图）、
image-batch（批量→ZIP）、file-convert（格式转换/ICO）、video-tools（压缩/转GIF/提音频）、
pdf-tools（合并/拆分/水印）、text-tools（JSON/文本）、qrcode（二维码）、
tts-clone（音色复刻交付）、voice-bubble（聊天语音气泡）、pixiv（找图/发图）。

## 扩展规则（写进 preset 第 6 条）

**没有卡的功能=没做完的功能**。以后每次新增能力，同一次改动里在 `capabilities-kb.js`
加一张卡（六个字段缺一不可），额度没拍板的先写"暂定"。

## 验证

1. `node tools/test-capabilities-kb.mjs`（29 项：12 卡齐套、别名命中、查不到给建议、默认配方）。
2. `node tools/test-image-edit.mjs`（47 项，含演示图真跑：金色别名回显、tile/-20/密度生效）。
3. 部署后真实链路：私聊问"水印怎么设置"→ misaki 调 `qq_help` 讲卡 → 说"看看效果"→
   她发演示图并按 `applied` 讲每个旋钮 → 用户改一个参数再演示一次。
